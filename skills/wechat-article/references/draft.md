# 草稿同步

`draft sync` 将已定稿的文章写入微信公众号草稿箱，不会群发或公开发布。同步读取 `article.json`，并使用 CLI 管理的 `service.json` 保存账号绑定、图片和草稿状态。

## 授权

用户在当前文章任务中明确要求将成稿上传、同步或保存到公众号草稿箱（例如“写好后上传到公众号草稿”“完成并同步到草稿箱”）时，即构成本次具体文章同步的授权。授权持续有效，直到约定的同步操作完成或用户撤回；大纲确认、资料补充、配置补齐等后续消息无需重述授权，也不为同一次操作重复确认。不要把该授权扩展到其他文章、其他账号或其他操作。

未明确要求同步时，不运行此命令，只交付文章文件；泛泛提到公众号、排版或发布计划不构成本次授权。如果提示词只说“上传到公众号”而无法判断目标是草稿箱还是公开发布，先确认目标；确认前不运行此命令。如果提示词要求公开发布或群发，本命令不适用；不要用草稿同步冒充发布，只交付文章并说明限制。授权仅覆盖当前文章的草稿创建，或 CLI 已记录草稿 ID 的更新；不包含群发、公开发布、覆盖其他文章、删除草稿或向其他第三方发送文章内容。

## 运行前检查

同步前检查：

- 当前文章任务已有未撤回、适用于本次操作的明确草稿同步授权；结合任务上下文判断，不只检查最新一条消息。
- 当前版本的评审达到通过线；只有本地浏览器视觉检查缺失时，可按[编辑与审校](editorial.md)如实标记暂评并继续，不冒称视觉通过。仅同步任务补做缺失检查，不擅自改稿。
- 公众号凭据已配置。
- `service.json` 中的账号摘要与当前账号匹配；已有远端记录没有账号摘要时，先核实归属。
- `service.json` 没有 `unknown` 或 `submitting` 的草稿状态，封面和正文图片也没有 `unknown` 或 `uploading` 状态；若有，先核实对应远端结果。
- 文章文件通过 CLI 校验：`article.json` 的标题、作者、摘要，以及引用的 Markdown、HTML、封面和正文图片。

```sh
wechat-article draft sync --dir drafts/<文章目录>
```

从仓库 checkout 本地运行时，使用 `node dist/index.js draft sync --dir drafts/<文章目录>`；首次构建和 CLI 可用性检查见[安装与配置参考](setup.md)。

上述相对路径命令假设文章在当前工作区内；CLI checkout 与文章工作区不同时，按[文章文件规范](article-files.md)使用 CLI 的绝对路径，并从文章工作区运行。

CLI 在请求 access token 前校验清单字段、路径包含关系、引用文件、图片扩展名和大小、被阻止的 HTML 元素或属性、占位符以及本地图片引用。它不比较 Markdown 与 HTML 的正文，也不检查文章超链接是否可达；这些由 Agent 在审校阶段完成。

普通命令成功时向 stdout 输出一个 JSON 对象，`status` 为 `success`，业务字段在 `data` 中；失败向 stderr 输出错误 JSON，并返回非零退出码。退出码 2 为输入或前置条件阻断，3 为微信接口或网络失败，4 为远端结果不明或未取得同步锁，1 为其他内部错误。根据退出码和 JSON 判断结果，不以文件生成、命令启动或单独出现 `media_id` 作为成功依据。`--help`、`--version` 为文本输出。

## CLI 行为

CLI 校验文件，按 SHA-256 复用或上传图片，之后创建新草稿或更新已记录的草稿 ID。没有 `draft_media_id` 时调用 `draft/add` 创建草稿并保存返回的 `media_id`；已有 ID 时调用 `draft/update` 更新该草稿。结果写入 `service.json`，并以 AppID 的 SHA-256 摘要绑定账号。草稿同步不是发布或群发。

同步成功后，报告 CLI 返回的 `action`（`saved` 或 `updated`）、`media_id` 和文章目录，并明确说明文章已保存为草稿、尚未公开发布。可用 `draft get --media-id <草稿ID>` 或 `draft list` 核对草稿是否存在。

`draft get` 只返回标题和摘要，`draft list` 只返回草稿 ID、更新时间等记录，不能据此报告远端正文、图片或微信样式已验证。若实际检查了微信后台或客户端预览，另行注明版本与范围。同步完成后更新本次评审记录中的远端保存状态，不把本地评审通过当作保存成功。

## 异常处理

| 情况 | 处理 |
| --- | --- |
| 凭据缺失 | 先完成本地文章交付，指引用户运行 `wechat-article config init`；不要在聊天或文章文件中粘贴密钥。 |
| 账号不匹配 | `service.json` 属于其他账号或账号归属未验证时，CLI 会拒绝同步；停止同步并核实账号归属和既有草稿；按下文“核实与恢复边界”处理，不自行迁移状态或覆盖远端草稿。 |
| 既有草稿归属不明 | 停止同步，先核实远端草稿归属；不猜测、不迁移、不覆盖其他草稿。 |
| 文件校验失败 | 报告 CLI 返回的 `blockers` 和修复建议；已有创作或修改授权时，仅在授权范围内修复并重新检查。仅同步任务未获修改授权时不改原稿，取得修改授权后再修复；不要把失败当成已同步。 |
| 明确失败 | 如实报告失败原因，保留本地文件；不声称成功。 |
| 结果不明确 | 远端写入结果不明确时，CLI 记录 `draft_status` 为 `unknown`（或停留在 `submitting`）并阻止再次同步。停止后续写入，先核对公众号草稿箱的服务端状态（可用 `draft get` 或 `draft list`），不盲目重试。退出码 4 也可能表示未取得同步锁；先确认是否有同步在运行，并核对后台。 |
| 再次修改并同步 | 视为一次新的草稿操作；`service.json` 已记录目标草稿 ID 且账号匹配时，按 CLI 规则更新该草稿，不扩大到其他草稿。 |

## 核实与恢复边界

结果不明时先保留本地文件、`service.json`、错误摘要和可能存在的锁，停止后续写入。对草稿用已知 ID 查询，必要时在公众号后台核对标题、时间与内容；图片上传结果不明不能由草稿列表是否存在推断。查询失败或未找到记录也不自动证明此前写入没有发生。

当前 CLI 没有状态恢复、账号迁移或解锁命令。Agent 不得删除、改名或清空 `service.json`，修改账号摘要、草稿 ID、状态字段，或删除 `.service-sync.lock` 来强行重试。核实后若 CLI 仍阻断，报告已确认的远端结果、剩余不确定项及需要维护处理的具体状态，保留本地交付并停止同步；恢复须另行明确授权和处理，不能把人工核实当作已自动解除阻断。
