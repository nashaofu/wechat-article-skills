# 草稿同步

`draft sync` 将已定稿的文章写入微信公众号草稿箱，不会群发或公开发布。同步读取 `article.json`，并使用 CLI 管理的 `service.json` 保存账号绑定、图片和草稿状态。

## 授权

用户本次提示明确要求将成稿上传、同步或保存到公众号草稿箱（例如“写好后上传到公众号草稿”“完成并同步到草稿箱”）时，即构成本次具体文章同步的授权。生成后无需为同一次操作重复确认，也不要把该授权扩展到其他文章、其他账号或其他操作。

未明确要求同步时，不运行此命令，只交付文章文件；泛泛提到公众号、排版或发布计划不构成本次授权。如果提示词只说“上传到公众号”而无法判断目标是草稿箱还是公开发布，先确认目标；确认前不运行此命令。如果提示词要求公开发布或群发，本命令不适用；不要用草稿同步冒充发布，只交付文章并说明限制。授权仅覆盖当前文章的草稿创建，或 CLI 已记录草稿 ID 的更新；不包含群发、公开发布、覆盖其他文章、删除草稿或向其他第三方发送文章内容。

## 运行前检查

同步前检查：

- 本次提示词确实要求同步。
- 公众号凭据已配置。
- `service.json` 中的账号摘要与当前账号匹配；已有远端记录没有账号摘要时，先核实归属。
- `service.json` 没有 `unknown` 或 `submitting` 的草稿状态；若有，先核实远端结果。
- 文章文件通过 CLI 校验：`article.json` 的标题、作者、摘要，以及引用的 Markdown、HTML、封面和正文图片。

```sh
wechat-article draft sync --dir drafts/<文章目录>
```

从仓库 checkout 本地运行时，使用 `node dist/index.js draft sync --dir drafts/<文章目录>`；首次构建和 CLI 可用性检查见[安装与配置参考](setup.md)。

CLI 在请求 access token 前校验清单字段、路径包含关系、引用文件、图片扩展名和大小、被阻止的 HTML 元素或属性、占位符以及本地图片引用。它不比较 Markdown 与 HTML 的正文，也不检查文章超链接是否可达；这些由 Agent 在审校阶段完成。

## CLI 行为

CLI 校验文件，按 SHA-256 复用或上传图片，之后创建新草稿或更新已记录的草稿 ID。没有 `draft_media_id` 时调用 `draft/add` 创建草稿并保存返回的 `media_id`；已有 ID 时调用 `draft/update` 更新该草稿。结果写入 `service.json`，并以 AppID 的 SHA-256 摘要绑定账号。草稿同步不是发布或群发。

同步成功后，报告 CLI 返回的 `action`（`saved` 或 `updated`）、`media_id` 和文章目录，并明确说明文章已保存为草稿、尚未公开发布。可用 `draft get --media-id <草稿ID>` 或 `draft list` 核对草稿是否存在。

## 异常处理

| 情况 | 处理 |
| --- | --- |
| 凭据缺失 | 先完成本地文章交付，指引用户运行 `wechat-article config init`；不要在聊天或文章文件中粘贴密钥。 |
| 账号不匹配 | `service.json` 属于其他账号或账号归属未验证时，CLI 会拒绝同步；停止操作，先核实账号归属和既有草稿，再按需要迁移状态，不擅自覆盖远端草稿。 |
| 既有草稿归属不明 | 停止同步，先核实远端草稿归属；不猜测、不迁移、不覆盖其他草稿。 |
| 文件校验失败 | 按 CLI 返回的 `blockers` 修正文章文件后重新检查；不要把失败当成已同步。 |
| 明确失败 | 如实报告失败原因，保留本地文件；不声称成功。 |
| 结果不明确 | 远端写入结果不明确时，CLI 记录 `draft_status` 为 `unknown`（或停留在 `submitting`）并阻止再次同步。停止后续写入，先核对公众号草稿箱的服务端状态（可用 `draft get` 或 `draft list`），不盲目重试。退出码 4 也可能表示未取得同步锁；先确认是否有同步在运行，并核对后台。 |
| 再次修改并同步 | 视为一次新的草稿操作；`service.json` 已记录目标草稿 ID 且账号匹配时，按 CLI 规则更新该草稿，不扩大到其他草稿。 |
