# 排版与图片

以 Markdown 定稿为内容依据制作公众号 HTML；仅排版任务不擅自改写原稿。按内容安排层级、段落间距和图文节奏，在有助于理解的位置使用图片或图示，避免装饰性堆图和连续大段文字。清单及目录示例见[文章文件规范](article-files.md)。

## HTML 与引用

- 使用正文 HTML 片段，关键样式直接写在元素的 `style` 中，避免依赖外部样式表、脚本或浏览器特有布局。浏览器显示正常不保证微信保留所有样式。
- 不使用 `script`、`iframe`、`object`、`embed`、`form`、事件属性、`javascript:` 或 `file://` 属性值；CLI 会阻止这些内容。交付前移除未填占位符、`{embed:...}` 和临时预览链接。
- 外部来源在正文相关位置用编号标注，在文末列出对应编号、描述性名称、可见的完整 URL 和链接。编号采用普通文本，不依赖 `href="#..."` 的页内跳转。长 URL 应能在窄屏换行；本地可点击不代表微信客户端允许访问全部外链。
- 宽表格转换为清晰可读的图片，放在原表格位置；Markdown 保留原始表格，HTML 用图片呈现，内容应一致。长表格可按信息结构拆图，不能为了塞入一张图而缩到难以阅读。
- 检查代码、长单词和图片是否造成横向溢出；不要仅通过整体缩小字号解决。图片使用稳定、易懂的文件名，与 HTML 一起交付。

## 图片约束

完整文章包必须提供封面，在 `cover` 中填写路径；正文图片按内容需要添加，在 `images` 中列出并由 HTML 引用，没有正文图片时使用空数组。封面支持 PNG、GIF、JPEG，文件不超过 10,000,000 字节；正文图片支持 PNG、JPEG，文件不超过 1,000,000 字节。这些是当前 CLI 的限制；扩展名应与实际格式一致，不能靠改扩展名转换图片。

HTML 本地图片路径相对于 HTML 文件，并对应清单中的文件；不使用 `..`、绝对路径、`data:`、查询参数或片段。优先将外部图片保存为已获使用权限的本地文件后纳入清单；不要直接引用任意外站图片。CLI 允许已有的 HTTPS `mmbiz.qpic.cn` 图片 URL，但允许引用不代表已核实其内容、归属或长期可用性。同步时 CLI 上传本地正文图片并替换为微信返回的 URL，不处理 CSS 背景图等其他图片引用方式。

封面检查主体在裁切后是否完整；图表和表格图片检查手机实际显示尺寸下的文字、标注和数据。引用外部图片保留必要的出处和授权说明，不虚构图片来源；生成图片不作为事实证据。

## 验证范围

具备预览能力时查看最终 HTML 的手机窄屏渲染，检查层级、留白、图片、代码、表格和长 URL；仅排版或图片任务只验证相应交付物。无法预览时仅报告静态检查，并将本地渲染标为待验证；完整成稿的版式分数和总分标为暂评，规则见[编辑与审校](editorial.md)。

本地浏览器渲染、微信后台或客户端预览、远端保存结果分别记录。只有实际查看微信中的对应版本，才能报告微信呈现已验证；不能由本地浏览器检查推断微信呈现通过，也不能由同步回执推断视觉通过。
