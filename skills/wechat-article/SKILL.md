# 微信公众号文章创作

用户提交一段文章提示词后，Agent 自动完成选题补全、研究、写作、排版和检查。提示词明确要求上传时，再把成稿同步到公众号草稿箱并反馈结果。草稿同步不等于公开发布；本 Skill 不包含群发或公开发布。

## 用户输入与默认行为

用户可以用自然语言描述需求，不需要填写固定表单。从提示词中提取：

- 主题或要解决的问题
- 目标读者和文章目的
- 文章风格、篇幅和必要结构
- 需要引用的资料、观点或案例
- 是否要同步到公众号草稿箱

提示词中的“写好后上传到公众号草稿”“完成并同步到草稿箱”等明确表述，视为对本次文章草稿同步的授权，生成后无需再为同一次操作重复确认。

只有写作信息确实不足、且无法根据上下文合理补全时才追问；上传授权不明确时按“上传授权与异常处理”处理。用户只是给出一个领域时，先自行拟定合适的角度和选题；若没有要求上传，则完成文章和交付文件，但不运行 `draft sync`。

## 端到端工作流

1. **解析提示词**：提取主题、读者、目的、语气、篇幅、资料要求和上传意图。复用用户提供的素材和上下文，不重复追问已有信息。
2. **确定选题与写作方案**：对宽泛主题自行收敛角度，确定文章主张和结构。只有存在无法合理推断的关键歧义时才询问用户。
3. **研究与事实核验**：按需查找可信来源，记录来源并核实关键事实。文章中区分事实、推断和观点；对不能核实的信息避免写成确定事实。按需阅读[研究参考](references/research.md)。
4. **撰写与审校**：产出 Markdown 成稿，检查事实、推理、表达、结构和链接。根据审校结果直接修订。按需阅读[编辑与审校参考](references/editorial.md)。
5. **制作公众号内容**：根据定稿生成公众号 HTML 和所需封面等文件。正文图片按内容需要添加，不为满足模板强行插图。按需阅读[排版与图片参考](references/layout-images.md)。
6. **检查与整理**：核对 Markdown 与 HTML 内容一致，检查链接有效、图片清晰且位置合理、文章元数据完整。具备预览能力时检查手机窄屏显示；无法预览时只报告静态检查。将交付内容放进文章目录，准备好 `article.json` 和 CLI 所需的引用文件；`service.json` 由 CLI 创建和维护。
7. **检查同步条件并上传草稿**：只有用户提示词明确要求同步草稿，才运行 `draft sync`。按[安装与配置参考](references/setup.md)确认 CLI 可用：先探测已安装的 `wechat-article` 命令；若当前仓库 checkout 有 `package.json` 和 `node_modules`，可在缺少构建产物时运行 `pnpm run build`，再使用 `node dist/index.js`。不得为单次同步静默安装全局包或依赖；没有可用命令且无法从现有 checkout 构建时，停止同步并说明 CLI 尚未就绪。随后运行 `config status`；只有状态为 `configured` 才继续检查账号、文章文件和图片并同步。若凭据缺失或不完整，完成本地文章交付并指引用户运行 `config init`，配置完成后再同步。按需阅读[草稿同步参考](references/draft.md)。
8. **报告交付**：简要说明文章主题、交付文件位置、检查范围，以及草稿同步状态。明确区分“已保存为草稿”和“已公开发布”；本流程不包含群发或公开发布。

## 上传授权与异常处理

- **授权范围**：授权仅覆盖本次文章，以及将其同步到公众号草稿箱的操作；不包括群发、发布、覆盖其他文章、删除草稿或向其他第三方发送内容。
- **用户没要求上传**：不上传，只交付文章文件。
- **上传目标不明确**：如果提示词只说“上传到公众号”而未说明草稿箱或公开发布，先确认目标；确认前不运行 `draft sync`。
- **提示词要求公开发布**：本流程只支持保存到草稿箱，不执行群发或公开发布；不要用 `draft sync` 冒充发布。只交付文章并说明这一限制。
- **凭据缺失**：完成文章并整理文件，说明需要先运行 `wechat-article config init` 配置公众号凭据。不要要求用户在聊天中粘贴密钥。
- **账号不匹配或已有草稿归属不明**：停止同步并说明原因，不擅自迁移或覆盖远端草稿。
- **上传结果明确失败**：如实报告失败原因，不声称成功。
- **上传结果不明确**：停止后续写入，先核实公众号草稿箱中的服务端状态；不盲目重试非幂等操作。CLI 记录为 `unknown` 或状态停在 `submitting` 时同样先核实。
- **再次修改并同步**：视为一次新的草稿操作；若 `service.json` 已记录目标草稿 ID 且账号匹配，则按 CLI 规则更新该草稿。不得借此扩大到其他草稿。

## 文件清单

每篇文章一个目录。Agent 编写 `article.json` 并准备其引用的 Markdown、HTML、封面和正文图片；CLI 首次同步时创建并维护 `service.json`。其余文件名和目录层级自由；引用路径相对于 `article.json` 所在目录。文章元数据位于 `article.json` 顶层。字段和服务端记录格式见 [CLI 参考](../../CLI.md)。CLI 只依赖 `article.json`、其清单引用文件，以及 CLI 维护的 `service.json`；选题、研究和审校过程材料按创作需要保存。

## 安全边界

CLI 只执行确定性操作：校验文件、检查账号、上传图片与文章、记录草稿状态；选题、研究、写作和审校由 Agent 完成。CLI 使用用户目录中的单账号凭据，向微信公众号官方接口发送封面、正文图片和文章内容。不得输出密钥或令牌。草稿操作结果不明确时先核实服务端状态，不自动重试。CLI 不提供群发或公开发布能力。
