# 微信公众号文章创作

新文章创作先做必要的初步核验并提交大纲，得到用户确认后再深入研究、写作、排版和检查。已有文章和单项任务按请求进入对应阶段。提示词明确要求上传时，再把成稿同步到公众号草稿箱并反馈结果。草稿同步不等于公开发布；本 Skill 不包含群发或公开发布。

## 用户输入与默认行为

用户可以用自然语言描述需求，不需要填写固定表单。从提示词中提取：

- 主题或要解决的问题
- 目标读者和文章目的
- 文章风格、篇幅和必要结构
- 需要引用的资料、观点或案例
- 是否要同步到公众号草稿箱

提示词中的“写好后上传到公众号草稿”“完成并同步到草稿箱”等明确表述，视为对本次文章草稿同步的授权。该授权在当前文章任务中持续有效，直到约定的同步操作完成或用户撤回；大纲确认、资料补充、配置补齐等后续消息无需重述授权，也不为同一次操作重复确认。

只有写作信息确实不足、且无法根据上下文合理补全时才追问；上传授权不明确时按“上传授权与异常处理”处理。新文章创作中，用户只是给出一个领域时，先自行拟定合适的角度和选题，再提交大纲等待确认；大纲未获确认前，不开始完整正文写作、排版或草稿同步。已有稿件及单项任务按下述入口执行。若没有要求上传，则交付请求范围内的结果，不运行 `draft sync`。

## 端到端工作流

先按请求选择入口，复用已有素材、已确认的大纲和仍适用于当前版本的检查结果，不重复执行无关阶段：

- **新文章或整体重写**：从选题和大纲开始；已有已确认且适用的大纲时直接复用。用户提供但尚未确认用于本次创作的大纲，先确认后继续。
- **评审已有文章**：进入审校阶段，默认只报告问题、位置、影响和修改建议，不修改原稿；修改按用户授权执行。没有 HTML 时只评估正文，不为凑齐评分生成 HTML 或封面。未要求落盘时直接在回复中报告。
- **局部修改**：只修改授权范围，并检查受影响的上下文、引用及已有 HTML、图片；涉及改变核心主张或整体结构时先提交调整后的大纲确认。
- **仅排版或制作图片**：以已有定稿为依据，进入制作与图文检查阶段，不擅自改写正文。
- **仅同步已有成稿**：进入同步前检查，复用与当前文件对应的评审记录；缺少记录时补做必要检查并记录结果，不重新选题或强制补走大纲确认。发现质量问题时报告阻断项，未获修改授权不改原稿。

以下为完整创作流程；单项任务只交付所请求阶段的结果，不强制生成完整文章包。

1. **解析提示词**：提取主题、读者、目的、语气、篇幅、资料要求和上传意图。复用用户提供的素材和上下文，不重复追问已有信息。
2. **初步核验并提交大纲**：对宽泛主题自行收敛角度，先核查关键前提和资料可获得性，避免以未经证实的主张规划全文；此阶段允许必要的检索和素材阅读，不展开完整写作。形成包含标题方向、目标读者、开篇思路、章节层级及各部分要点的大纲，标出待验证假设，发送给用户确认。只有存在无法合理推断的关键歧义时才先询问。等待用户确认；根据反馈修改大纲并再次确认，未确认前不进入后续创作步骤。
3. **研究与事实核验**：大纲确认后，按需查找可信来源，记录来源并核实关键事实。文章中区分事实、推断和观点；对不能核实的信息避免写成确定事实。按需阅读[研究参考](references/research.md)。
4. **撰写与正文初审**：按确认的大纲产出 Markdown 成稿，检查硬性问题并评估目标契合度、事实可靠性、结构与逻辑、表达与可读性四项；先修正内容问题，不提前计算完整总分。文章兼顾手机与 PC 端阅读，使用清晰的小标题和简短段落，控制单段长度，避免长篇文字连续堆叠；删去重复和不必要的铺陈，让读者容易理解并顺畅阅读。成稿应自然、具体，贴合目标读者和用户指定的语气，避免模板化表达和明显的 AI 腔；按[编辑与审校参考](references/editorial.md)逐项检查、评分并回炉。
5. **制作公众号内容**：根据定稿生成 HTML、封面和所需正文图片，按[排版与图片参考](references/layout-images.md)安排图文节奏、引用、宽表格和兼容格式。依照[文章文件规范](references/article-files.md)准备清单与引用文件。
6. **图文评审与整理**：核对 Markdown 与 HTML 的内容、引用和图片，按[编辑与审校参考](references/editorial.md)完成五项评分、必要的回炉和最终复核。具备预览能力时检查最终 HTML 在手机窄屏和 PC 宽屏下的渲染；分别记录静态检查、本地渲染、微信预览和远端保存的验证范围，不将其中一种检查当作其他检查通过的证明。
7. **交付评审报告**：将评分依据、证据、修订记录、验证状态及结论写入文章目录的 `review.md`，不插入正文。报告内容和最多两轮回炉规则见[编辑与审校参考](references/editorial.md)；未通过时交付“待完善稿”并暂停同步。
8. **检查同步条件并上传草稿**：评审质量达到通过线，且当前文章任务已有未撤回、适用于本次操作的明确草稿同步授权时，才按既有条件运行 `draft sync`；评分通过不构成上传授权。若唯一未完成项是浏览器视觉验证，且静态检查与质量评分达到要求，可如实标为“静态检查通过，视觉待验证”并继续遵循既有同步条件，不冒称视觉通过。按[安装与配置参考](references/setup.md)确认 CLI 可用：先探测已安装的 `wechat-article` 命令；若当前仓库 checkout 有 `package.json` 和 `node_modules`，可在缺少构建产物时运行 `pnpm run build`，再使用 `node dist/index.js`。不得为单次同步静默安装全局包或依赖；没有可用命令且无法从现有 checkout 构建时，停止同步并说明 CLI 尚未就绪。随后运行 `config status`；只有状态为 `configured` 才继续检查账号、文章文件和图片并同步。若凭据缺失或不完整，完成本地文章交付并指引用户运行 `config init`，配置完成后再同步。按需阅读[草稿同步参考](references/draft.md)。
9. **报告交付**：简要说明文章主题、交付文件位置、评审结论、验证范围，以及草稿同步状态。明确区分“已保存为草稿”和“已公开发布”；本流程不包含群发或公开发布。

## 上传授权与异常处理

- **授权范围**：授权仅覆盖本次文章，以及将其同步到公众号草稿箱的操作；不包括群发、发布、覆盖其他文章、删除草稿或向其他第三方发送内容。
- **用户没要求上传**：不上传，只交付文章文件。
- **上传目标不明确**：如果提示词只说“上传到公众号”而未说明草稿箱或公开发布，先确认目标；确认前不运行 `draft sync`。
- **提示词要求公开发布**：本流程只支持保存到草稿箱，不执行群发或公开发布；不要用 `draft sync` 冒充发布。只交付文章并说明这一限制。
- **凭据缺失**：完成文章并整理文件，说明需要先运行 `wechat-article config init` 配置公众号凭据。不要要求用户在聊天中粘贴密钥。
- **账号不匹配或已有草稿归属不明**：停止同步并说明原因，不擅自迁移或覆盖远端草稿。
- **上传结果明确失败**：如实报告失败原因，不声称成功。
- **上传结果不明确**：停止后续写入，先核实公众号草稿箱中的服务端状态；不盲目重试非幂等操作。CLI 记录为 `unknown` 或状态停在 `submitting` 时同样先核实。
- **再次修改并同步**：视为一次新的草稿操作；若 `service.json` 已记录目标草稿 ID 且账号匹配，则按 CLI 规则更新该草稿。不得借此扩大到其他草稿。

## 文件清单

完整文章包每篇一个目录。Agent 编写 `article.json` 并准备其引用的 Markdown、HTML、封面和正文图片；CLI 首次同步时创建并维护 `service.json`。清单示例、字段和路径约束见[文章文件规范](references/article-files.md)。完整创作交付必须包含 `review.md`；其他选题、研究和写作过程材料按需保存。单项任务的交付范围按对应入口执行。

## 安全边界

CLI 只执行确定性操作：校验文件、检查账号、上传图片与文章、记录草稿状态；选题、研究、写作和审校由 Agent 完成。CLI 使用用户目录中的单账号凭据，向微信公众号官方接口发送封面、正文图片和文章内容。不得输出密钥或令牌。草稿操作结果不明确时先核实服务端状态，不自动重试。CLI 不提供群发或公开发布能力。
